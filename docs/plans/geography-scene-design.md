# 地理场景设计方案 · 数字地球探究

> 定位：平台第 4 个学科场景插件（数学·几何 / 物理·力学 / 信息科技·编程 之外的地理）。
 > 核心体验：手势旋转地球 → 指向选中区域 → 放大进入 → 区位/地形/人文资料 + AI 讲解。
 > 设计原则：确定性算法优先（坐标换算、区域判定可单元测试），LLM 只负责自然语言表达，离线可降级。

## 1. 教学目标

- 经纬网与球面定位：通过旋转地球和实时经纬度读数建立"经纬度=球面坐标"的直觉；
- 区域地理认知：区位（半球/大洲/海陆）、地形地貌、人文特征的关联分析；
- 探究闭环：根据线索定位区域（任务 A）→ 验证 → 解释区位与地形/人文的关系（任务 B）。

## 2. 技术选型：离线优先的两层架构

| 层 | 方案 | 理由 |
|---|---|---|
| 三维地球 | three.js SphereGeometry + 离线等距圆柱贴图（NASA Blue Marble / Natural Earth，2–5 MB） | 复用 CubeView 的 three.js 管线；完全离线；课堂无网可演示 |
| 区域判定 | Natural Earth 110m 简化边界 GeoJSON（~1 MB）+ 点在多边形内判定 | 纯函数、确定性、可单元测试；国家级精度足够 |
| 区域资料 | 内置资料卡（七大洲 + 20–30 个重点区域，离线保底）+ 可选 LLM 生成 | 有网增强、无网降级，符合"规则优先、LLM 表达"的架构原则 |
| 详细地图瓦片 | 不做（课程版边界） | GIS 级瓦片（Cesium/在线影像）体积与复杂度跳档，留给后续阶段 |

素材放 `public/assets/`（earth 贴图 + world GeoJSON），随 git 提交，克隆即离线可用。

## 3. 手势交互规范（复用统一语义，零新增词汇）

| 操作 | 手势 | 鼠标等价 | 说明 |
|---|---|---|---|
| 旋转地球 | 捏合地球任意处拖动（旋转模式） | 按住拖动 | 相对位移映射 yaw/pitch（同几何参数拖动内核），松开后惯性衰减 |
| 选择区域 | 选择模式下指向 + 捏合"点击" | 单击 | raycast 得经纬度；捏合位移 < 3% 屏宽才算点击（防旋转误选） |
| 模式切换 | 比"2"=旋转，比"3"=选择（场景化解释） | 工具栏按钮 | 同几何"操作模式"的显式模式原则 |
| 进入/返回 | 按钮（手势点击） | 双击进入 / Esc 返回 | 进入后显示区域详情视图 |
| 缩放 | 按钮 +/− | 滚轮 | 朝选中点推近相机 |
| 语音 | "旋转模式 / 选择模式 / 进入区域 / 返回地球 / 重置" | — | 扩展 matchVoiceCommand 场景规则 |

实时反馈：光标落在地球上时状态栏显示当前经纬度（经纬网教学点）；选中区域描边高亮。

## 4. 界面与流程

**两级视图：**

1. **地球视图**：三维地球 + 经纬网（可开关）+ 大洲边界 + 选择标记；侧栏三栏结构（任务 / 实时读数 / 提示与反思）与其他场景一致；
2. **区域视图**：选中区域放大（贴图局部 + 边界多边形）+ 三块资料（区位 / 地形地貌 / 人文特征）+ 地球上的位置小图（"你在哪"）+ "返回地球"。

**任务结构（对齐平台四模式）：**

| 模式 | 内容 | 判定 |
|---|---|---|
| 演示模式 | 自由旋转、选择、AI/资料卡讲解 | — |
| 任务 A · 线索定位 | 给出区位线索（如"横跨赤道、拥有最大热带雨林的国家"），旋转地球选中作答 | 确定性：选中点是否落在目标区域多边形内 |
| 任务 B · 区位分析 | 选中任一区域，回答引导问题（如"该区域地形与人口分布的关系"） | 解释提交 + 关键词规则检查（弱判定，如实标注） |

任务 A 的线索库内置 10–15 条（离线），每条绑定目标区域多边形与提示分级。

## 5. LLM 接入设计（可选、显式、可降级）

- **入口**：区域视图中"AI 讲解"按钮（显式触发，不自动调用）；
- **配置**：设置面板填 OpenAI 兼容 API 地址 + 模型名 + key（存 localStorage，用户自备，不入 git、不上传）；
- **请求**：结构化 prompt（区域名 + 类别[区位/地形/人文] + 面向中学生 + 200 字内），只发区域名等文本，**不发送任何摄像头/日志数据**；
- **降级**：无 key / 网络失败 → 显示内置资料卡并提示；内置卡与 AI 内容视觉区分（AI 标注"AI 生成"）；
- **教学增强**：讲解末尾附带一个苏格拉底式追问，进入学习日志；
- 边界诚实声明：AI 内容不做事实判题依据；任务判定始终是确定性规则。

## 6. 插件结构（对齐平台契约）

```text
src/scenes/geography/
├── geoMath.ts          # 经纬度↔三维向量、屏幕 raycast、点在多边形判定（纯函数）
├── geoMath.test.ts     # 换算与判定的正确性测试（含球面边界：极点、日期变更线）
├── regionData.ts       # GeoJSON 加载、区域查找、内置资料卡、任务 A 线索库
├── llm.ts              # 可选讲解生成（fetch + 会话缓存 + 降级）
└── GeographyScene.tsx  # 三维地球 + 区域视图 + 任务流 + 手势策略
```

注册：registry.ts 加一行；SceneId 增加 'geography'；语音规则扩展场景短语。

## 7. 防误触与状态管理

- 旋转拖动中不触发选择（位移阈值区分点击/拖动）；
- 追踪丢失/取消：正在旋转时按几何场景同样的回滚策略（恢复旋转前姿态）；
- 模式切换、进入/返回区域时结束进行中的操作（平台既有行为）；
- 页面隐藏：地球渲染用 rAF 无妨（无需后台运行），选择/旋转状态不丢失。

## 8. 测试计划

- geoMath 单元测试：经纬度↔向量往返、屏幕点→经纬度（给定相机参数）、点在多边形（含跨界多边形）、极点边界；
- regionData：线索库目标区域可被自身多边形命中；
- 集成测试（jsdom）：场景切换、模式切换按钮、任务 A 线索→选中（模拟点击换算）→判定对错、AI 按钮在无 key 时降级提示；
- 现有全量测试零回归。

## 9. 工作量与里程碑

| 步骤 | 内容 | 估时 |
|---|---|---|
| 1 | 素材准备（贴图 + GeoJSON 精简） | 0.5 天 |
| 2 | geoMath + 区域判定 + 测试 | 0.5–1 天 |
| 3 | 地球渲染 + 旋转/选择/缩放交互（含手势） | 1–1.5 天 |
| 4 | 区域视图 + 资料卡 + 任务 A/B | 1 天 |
| 5 | LLM 接入 + 降级 + 收尾联调 | 0.5–1 天 |

合计约 4–5 天；每步独立提交。

## 10. 边界声明（写进 README）

- 贴图地球不是 GIS 精确地图，无实时影像/地形瓦片；
- 区域判定为国界级精度（110m 简化边界），不保证省州级准确；
- AI 讲解需要联网与用户自备 API key；离线时功能完整降级为内置资料卡；
- 不上传任何本地数据到 LLM 服务，仅发送区域名称与类别。
